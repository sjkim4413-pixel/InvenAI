# 실사 및 재적재 현장 로그 수정

기존 홈 최근 현장 로그와 작업·이상 이력은 `stockHistory/{company}/events`만 읽었다. 실사 오적재는 별도 `auditAlerts` 문서로 생성·상태 변경되며 이력이 저장되지 않아 해당 화면에서 보이지 않았다. 기존 전산 재고 재검수 요청 역시 회신 위치·수량 대신 변경 전 재고 값을 이력에 저장하고 있었다.

수정 내용:

- `auditHistory/{company}/events`에 발견, 재적재 회신, 재조치 요청, 검수 승인을 불변 이력으로 저장한다. 알림 생성·변경과 이력은 같은 트랜잭션이며 `getAfter`로 회사·알림·처리자·상태·위치·상품·메모·시각 일치를 검증한다. 중복 전송은 추가 발견 이력을 만들지 않는다.
- `WarehouseHistory.listen`은 기존 재고 이력, 실사 이력, 기존 알림에서 확인 가능한 사실을 병합한다. 날짜순 최근 100건을 반환하고 홈은 선택 창고의 최근 5건을 표시한다. 로그 화면으로 이동할 때 창고 조건을 유지한다.
- 재적재 회신은 작업·이상 이력 양쪽에서 표시한다. 검수 승인에 따라 확정된 기존 재고의 이동도 작업 이력에 표시한다. 처리 완료 필터는 두 종류의 검수 승인을 포함한다.
- 기존 전산 재고의 재검수 요청은 회신한 위치와 수량을 남긴다. 검수 전 전산 재고 위치·수량은 유지되며 검수 승인 때 확정한다. 이전 앱의 변경 전 재고 형식도 규칙에서 허용한다.
- 실사 알림 이력에는 테스트 여부, 발견 상품, 전산 기준, 출발·목표 위치, 메모와 처리자를 표시한다. 실사로 수량이 확인되지 않은 경우 수량 미확정으로 표시한다. 기록을 누르면 실사 이력 상세가 열리며 다른 상품의 전산 상세로 이동하지 않는다.

기존 데이터:

과거 알림의 `createdAt`으로 발견을 표시하고 `updatedAt`과 최종 상태로 마지막 처리 결과를 표시한다. 이미 저장한 새 이력과 중복되지 않는다. 과거에 저장하지 않은 중간 재조치 단계·시각·최종 검수자 UID는 복구하거나 추정하지 않는다. 새 이력에는 실제 실행자의 UID와 서버 시각이 남는다. 실사 이력을 남기는 과정에서 실제 재고를 자동 변경하지 않는다.

검증:

- 단위 테스트 48개 통과. 병합 순서·중복 제거·같은 시각의 서로 다른 이력·필터·반복 재조치 포함.
- 로컬 Firestore 이력 규칙 29개 통과. 발견→회신→재조치→회신→승인 5개 기록, 대상 재고 불변, 회사 격리·위조·변조 차단, 이전 이력 형식 호환 포함.
- 기존 실사 알림 규칙 31개, 관리자 가입 승인 규칙 37개 통과.
- Android 실제 화면 통합 시나리오 통과 (`android-tests.log`). 홈 발견 로그, 적재자 작업·이상 탭, 두 번의 재적재, QA 재조치·승인, 기존 알림 표시, 전산 재고의 회신 위치·수량과 승인 후 이동, 처리 완료 필터, 홈 최종 이동 로그를 확인했다.
- 모든 쓰기 시험은 로컬 Firebase 18861/18862에서 수행했다. 운영 재고 쓰기는 하지 않았다.

사용자는 적재자·검수자 앱을 모두 수정 APK로 업데이트해야 모든 새 중간 처리 이력이 남는다. APK는 프로젝트 루트의 `app/build/outputs/apk/debug/app-debug.apk`에 있다. 운영 규칙 배포 로그와 전후 규칙은 이 폴더에 보관한다.

공식 근거: [Firestore 트랜잭션과 원자적 작업 검증](https://firebase.google.com/docs/firestore/manage-data/transactions#data_validation_for_atomic_operations).
