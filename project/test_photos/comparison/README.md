# F05 정상·오적재 비교 시연

현재 앱에서는 아래 비교 2장을 제거하고 [원본 6장 + 오적재 6장](../paired44/README.md)으로 대체했습니다. 아래 기록과 사진은 이전 검증을 위한 보관 자료입니다.

현재 참고 사진 6장의 라벨·위치 대조 개선 결과와 최신 `.43` 검증 기록은 [accuracy43](../accuracy43/README.md)에 있습니다. 아래 비교 사진 01·02의 상품 교환 시연과는 판정 범위가 다릅니다.

앱의 **AI 실사 → 테스트 이미지 → 정상·오적재 비교**에서 다음 두 사진을 선택합니다.
사진 확인 화면에서 **이 사진 분석**을 누르고, 결과 사진의 테두리를 눌러 관측 상품과 전산 상품을 확인합니다.
Firebase 회사 `ABC-002`의 승인된 QA 계정과 로컬 F03 서버가 필요합니다.

| 선택 항목 | 실제 OCR 판독 순서: 왼쪽 / 가운데 / 오른쪽 | 확인된 앱 표시 |
| --- | --- | --- |
| 테스트 01 · 정상 배치 비교 | HPX-111 / HPX-222 / HPX-333 | 초록 3곳 · 일치 3건 · 확인 필요 0건 |
| 테스트 02 · 오적재 배치 비교 | HPX-222 / HPX-111 / HPX-333 | 빨강 2곳 + 초록 1곳 · 일치 1건 · 확인 필요 2건 |

두 사진은 AI 이미지 편집으로 제작했습니다. 기존 QAC 사진의 주요 가전 적재 구역을 참고하여 정상 기준 사진을 만들고, 왼쪽과 가운데 상품 묶음을 자연스럽게 교환했습니다. 선반 위치 라벨과 오른쪽 상품은 유지했습니다. `HPX-*`는 비교 시연용 가상 상품 코드입니다.

테스트 사진 제목은 모두 `테스트 NN · 설명` 형식입니다. 현재 선택 목록은 비교 2장과 참고 6장으로 총 **8장**입니다. 정상 일치율이 낮다고 사용자가 지정한 **기존 06~11번**은 `enabled: false`로 제외하고, 원본 자료는 보관합니다. 기존 번호를 유지해 선택 가능한 번호는 **01~05, 12~14**입니다. 위 두 장을 기본 목록에 표시하고 참고 사진은 **기존 테스트 6장** 버튼으로 선택합니다.

2026-11-24 추가 수정: `276ec63e-e08f-4915-b585-582e9529bdaa.png`의 맨 위 줄 두 번째 파렛트 아래에 `A02-5F` 라벨을 추가했습니다. AI 편집 결과의 라벨 영역만 원본에 반영해 다른 영역의 픽셀은 그대로 보존했습니다. 수정 사진의 서버 등록 해시와 해당 테스트 재고 한 건의 누락 라벨 정보를 함께 갱신했습니다. 수량과 재고 상태는 유지했습니다. 상세 기록은 `test_photos/label_corrections`에 있습니다.

## 판정 범위

이 비교는 **기능 5번의 색상 표시·상세 창·상품 대조 흐름**을 검증합니다. 두 사진의 SHA-256에 한정해 사람이 지정한 동일한 위치 영역 세 곳을 사용하며, 자동 객체 탐지 성능이나 현장 정확도를 측정하지 않습니다. 일반 사진의 `live` 분석과 기존 랙 라벨 테스트 모드는 별도로 유지합니다.

상품 코드는 각 사진의 실제 픽셀에서 EasyOCR로 읽습니다. 원본과 대비 보정 영상 두 판독이 같아야 하며, 두 판독 모두 기존 OCR 기준 0.70 이상이고 하나 이상은 0.85 이상이어야 합니다. 파일명으로 정상·오적재 결과를 선택하지 않습니다. 흐리거나 판독이 충돌하면 주황색 확인 필요로 보류합니다.

위치 라벨 OCR은 일부 신뢰도가 낮아 위치 연결에 사용하지 않습니다. 이 시연은 사람이 사전 표시한 위치를 사용한다는 사실을 화면과 상세 창에 표시합니다. `verification_passed`, `product_location_verified`, `quantity_verified`는 모두 `false`이고, 초록색은 별도 `test_product_location_match` 필드로 표시합니다. 탐지 신뢰도는 제공하지 않습니다.

## 공통 전산 기준

Firestore 프로젝트 `warehouseqa-8c262`, 데이터베이스 `(default)`, 회사 `ABC-002`, 창고 **AI 상품·위치 비교 테스트 창고**를 사용합니다. 두 사진은 항상 다음 동일한 재고와 비교합니다.

| 위치 | 전산 상품 | 수량 의미 |
| --- | --- | --- |
| QAC02-5F-01 | HPX-111 · 흰색 가전 포장 묶음 | 포장 묶음 1개 |
| QAC02-5F-02 | HPX-222 · 갈색 가전 포장 묶음 | 포장 묶음 1개 |
| QAC03-5F-01 | HPX-333 · 연녹색 가전 포장 묶음 | 포장 묶음 1개 |

상자 개수는 자동 검증하지 않습니다. 비교 결과로 Firestore 재고를 수정하지 않으며, 시연 모드에서는 운영 재고의 이상 조치 요청을 제공하지 않습니다. 수동 확인 기록은 기존 기능대로 기기에 저장하며 사진·사용자·창고·테스트 범위별로 구분됩니다.

`import_inventory.cjs`는 고정된 세 문서만 대상으로 충돌 검사를 수행합니다. `apply`는 존재하지 않는 문서만 생성하고, 기존 내용이 다르면 중단합니다. 동일 문서는 덮어쓰지 않습니다. `verify`는 회사 전체 재고를 읽어 기록된 실제 OCR과 다시 대조합니다.
