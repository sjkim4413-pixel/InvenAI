# 이상 재고 기기 푸시 알림

2026-11-25. 최신 앱: `app/build/outputs/apk/debug/app-debug.apk`.

## 사용 방법과 동작

적재자 계정으로 로그인한 뒤 알림 권한을 허용합니다. 적재자 홈의 **이상 재고 기기 알림 설정**에서 연결 상태를 확인하고 Android의 알림·소리·팝업 설정을 열 수 있습니다.

실사 오적재를 저장하면 같은 회사의 등록된 적재자 기기에 FCM 데이터 메시지를 보냅니다. 기존 수동 오적재 조치 요청과 재조치 요청도 같은 경로를 사용합니다. 기기는 로그인 계정·회사·적재자 권한과 현재 이상 상태를 서버에서 확인하고 소리·진동·상단 기기 알림을 표시합니다. 알림을 누르면 해당 실사 조치 화면 또는 재고 상세 화면으로 이동합니다.

다른 앱 사용 및 화면 꺼짐 수신을 지원합니다. 확인 작업은 FCM 고우선순위 메시지에 맞춰 WorkManager의 긴급 작업으로 처리하며, 이전 Android에서는 확인하는 동안 짧은 무음 진행 알림을 사용합니다. 기기 토큰 등록·갱신과 검수자의 발송 요청도 기기 내 작업 큐에 보관하고 연결 복구 시 재시도합니다. Firestore 실시간 수신과 FCM이 겹쳐도 같은 상태 변경의 기기 알림을 중복 표시하지 않습니다.

**현재 PC 분석 서버가 켜져 있고 앱에서 연결할 수 있어야 새 푸시를 발송할 수 있습니다.** FCM은 무료로 제공되며 기존 서버를 사용합니다. Firebase 요금제 변경이나 Cloud Functions 추가는 하지 않았습니다. [Firebase 요금 안내](https://firebase.google.com/pricing).

## 권한과 보관

- 기기 등록은 Firebase ID 토큰으로 인증한 LOADER만, 발송은 QA만 할 수 있습니다. 서버가 현재 회사·역할과 원본 이상 문서를 확인합니다.
- 메시지에는 대상 계정·회사·문서·이벤트 식별자만 담습니다. 재고 상세 내용은 기기의 현재 로그인 권한으로 다시 조회합니다. 다른 계정·회사·이미 처리된 알림은 표시하지 않습니다.
- 발송 이력은 이벤트와 기기별로 중복을 막고, 일부 기기 발송 실패 시 성공한 기기를 다시 발송하지 않습니다. 무효 기기 토큰은 등록에서 제거합니다.
- 전용 서버 계정 `invenai-fcm-sender`에는 `roles/firebasecloudmessaging.admin`만 부여했습니다. 재고 조회 권한은 추가하지 않았습니다. 원본 확인에는 요청한 사용자의 기존 Firebase 권한을 사용합니다.
- 발송 키는 프로젝트의 `.secrets/fcm-sender.json`, 기기 등록·발송 이력은 Python 서버의 `audit_private/push.sqlite3`에 보관합니다. 두 폴더는 현재 Windows 사용자만 접근하도록 제한했고 Git에서 제외했습니다. 서버 키와 기기 토큰은 APK나 검사 로그에 넣지 않습니다.
- 운영 재고 수량·위치와 Firestore 보안 규칙은 변경하지 않았습니다. 기존 12장 테스트 사진과 창고 선택 동작도 유지합니다.

- [실제 발송 시각](real-fcm-send.json), [기기 표시 시각](real-device-receipt.json), [최종 검증](verification.json). 이번 검증에서는 발송 시작부터 기기 표시까지 약 3초가 걸렸습니다. 이 값은 해당 테스트의 측정값입니다.

기기 검사의 인증·재고는 로컬 Firebase Auth/Firestore를 사용하며, 실제 FCM은 검사 에뮬레이터 한 대에만 발송했습니다. 운영 사용자로 로그인해 실사부터 수행한 전체 운영 계정 검증과는 구분합니다. 현재 앱의 분석 서버 주소는 에뮬레이터용 `10.0.2.2:8082`이므로 실제 휴대폰 사용 시 접근 가능한 서버 연결을 먼저 구성해야 합니다.
