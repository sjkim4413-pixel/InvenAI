## 자동 알림 동작

1. 검수자가 사진을 분석하면 서버가 확인한 **오적재 판정(code 2)**을 자동 등록합니다. 정상이나 주황색 확인 필요 판정은 자동 발송하지 않습니다.
2. 같은 회사의 **LOADER 계정으로 실행 중인 앱**이 Firestore에서 이를 실시간으로 받습니다. 적재자 홈 배너, 알림 팝업, 권한이 허용된 기기 알림으로 표시합니다. 여러 위치의 알림이 연속으로 도착하면 열린 팝업의 건수와 내용을 갱신합니다.
3. 적재자는 **오적재 관리 → 알림 상세 및 조치 → 조치 완료·재검수 요청**으로 회신합니다. 검수자는 재확인 후 **재검수 완료** 또는 **재조치 요청**을 선택합니다.
4. 같은 분석 작업·위치·상품 조합은 다시 렌더링하거나 재요청해도 중복 등록하지 않습니다. 새 사진을 업로드한 새 실사는 새 작업으로 구분합니다. 전송 대기 자료는 사용자·회사별 기기 저장소에 보관하고, 연결 복구·화면 재진입 시 재시도합니다.

알림은 새 `auditAlerts` 경로에 보관합니다. 실사에서 발견한 문제와 전산 재고를 분리하여, 알림 등록·회신·검수로 재고 수량과 위치를 자동 변경하지 않습니다. 기존 재고 조치 기능도 유지합니다. 현재 12장의 테스트 사진에서 발생한 알림은 **테스트**로 표시하며 기존 100% 기준 재고를 보존합니다.

기기 알림은 클라이언트 Firestore 실시간 수신 후 생성하는 알림입니다. 앱이 완전히 종료된 상태의 FCM 원격 푸시까지 구현한 것은 아닙니다. Android 13 이상에서는 기기 알림 권한을 요청하며, 미허용 상태에서도 앱 내부 배너와 팝업은 동작합니다.

## 접근 규칙과 운영 적용

`warehouseqa-8c262/(default)`의 기존 재고·회원·이력 규칙은 유지하고 새 알림 경로만 추가했습니다. 동일 회사 QA만 알림을 생성할 수 있고, 생성 시 현재 재고 문서의 회사·상품·위치·테스트 구분과 대조합니다. 회사·생성자·상품·분석 작업 등은 변경할 수 없습니다. 적재자는 조치 회신만 할 수 있으며 최종 완료·재조치는 검수자가 처리합니다. 필수 필드, 허용 필드, 길이, 타임스탬프와 상태 전이를 검증합니다.

운영 적용 전 규칙 백업과 외부 변경 여부 확인, 로컬 권한 검사, Firebase 배포 사전 검사를 수행했습니다. 배포 후 운영 규칙이 검증한 소스와 동일한지도 다시 확인했습니다. 검사 중 운영 재고나 운영 알림을 생성하지 않았습니다. 테스트 계정과 테스트 알림은 로컬 에뮬레이터에만 만들었습니다.
