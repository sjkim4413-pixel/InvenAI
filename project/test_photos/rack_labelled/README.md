# 추가 테스트 사진

원본 `test_photos`에서 사진 3장을 골라 위치 라벨 26개를 추가했다. 원본 사진은 수정하지 않았다. 새 사진은 이 폴더와 `test_image_ai`에 동일한 내용으로 저장한다.

| 앱에서 선택할 파일 | 장면 | 테스트 위치 |
|---|---|---:|
| `QAE_rack_labels.png` | 가전제품 정면 진열 | 12 |
| `QAF_rack_labels.png` | 장난감 정면 진열 | 10 |
| `QAG_rack_labels.png` | 비스듬한 포장 팔레트 | 4 |

기존 라벨 사진 5장을 유지해 등록된 라벨 사진은 총 8장이다. 이전 포장 외형 테스트 사진 4장도 앱에 포함되므로 앱의 전체 내장 사진은 12장이다.

## 앱에서 사용

1. 새 사진이 포함된 APK를 설치하고 `ABC-002`의 QA 계정으로 로그인한다.
2. AI 실사 촬영 화면에서 **테스트 이미지**를 누른다.
3. `QAE_rack_labels.png`, `QAF_rack_labels.png`, `QAG_rack_labels.png` 중 하나를 선택하고 분석한다.

사진별 전산 위치는 `AI 실사 추가 테스트 창고`의 테스트 재고로 연결한다. 사진의 서버 측 해시가 등록 목록과 일치해야 테스트 모드를 사용할 수 있다. 일반 사진을 같은 이름으로 바꿔도 등록되지 않는다. 앱에 내장되는 사진은 빌드 시 복사되므로 새 APK에 반영해야 한다.

## 재현과 데이터

- `extra_photos.json`: 원본 파일, 라벨 위치, 사람이 표시한 적재물 경계와 설명.
- `prepare_extra_photos.py`: EXIF 방향을 적용하고 긴 변을 2200픽셀 이내로 맞춘 뒤 동일한 라벨 사진과 메타데이터를 재생성한다. 이미 있는 파일의 내용이 다르면 덮어쓰지 않고 중단한다.
- `extra_annotations.json`: 생성된 사진·원본 해시와 정규화한 위치 라벨·적재물 경계. 이 경계는 모델에 정답으로 입력하지 않는다.
- `rack_locations_extra_ABC-002.csv`: 새 위치 26개의 구역·랙·단·사진 매핑. 기존 `rack_locations_ABC-002.csv`의 110개 위치와 함께 사용한다.
- `extra_inventory_plan.json`: 새 테스트 재고 26건. `isTestData=true`, `dataSource=SIMULATED_AI_IMAGE_ERP`로 구분한다.
- `import_extra_inventory.cjs`: 동일한 기존 테스트 문서는 확인만 하고, 없는 문서만 원자적으로 생성한다. 다른 내용의 기존 문서나 상품·위치 충돌이 있으면 중단한다.
- `extra_inventory_readback.json`: 등록 후 Firestore에서 다시 읽어 계획과 일치하는지 확인한 테스트 재고.
- `extra_analysis_report.json`: 실제 업로드·OCR·탐지·테스트 라벨 대조 결과. 미탐지와 보류도 전체 26개 위치에 포함한다.

프로젝트 루트에서 재생성한다.

```powershell
.\app\src\main\java\com\example\myapp\F03_py\.venv\Scripts\python.exe -B .\test_photos\rack_labelled\prepare_extra_photos.py
```

## 검증 범위

백엔드 테스트 127개가 통과했다. 실제 사진 업로드부터 OCR·탐지·F04 테스트 대조까지 실행한 결과, `QAE`는 12곳 중 9곳이 일치했고 `QAF` 10곳과 `QAG` 4곳은 모두 보류됐다. 총 26곳 중 9곳의 라벨 일치가 확인됐으며, 결과가 생성되지 않은 위치도 보류에 포함했다. 등록·업로드 성공과 자동 판정 성공은 별도로 집계한다.

APK 빌드가 성공했고, APK 안의 테스트 사진 12장이 원본 테스트 파일과 바이트 단위로 일치하는 것을 확인했다. 라벨 등록 해시 8개도 모두 일치했다. 확인 기록은 `extra_package_verification.json`에 있다. 로컬 서버는 `2026-11-21.40`으로 재시작했고 `/health`에서 정상 상태와 보조 탐지기 사용 가능 상태를 확인했다.

사진 분석 검사는 등록 후 Firestore에서 다시 읽은 테스트 재고를 사용했다. 로컬 HTTP 검사의 인증과 재고 로더는 테스트용으로 대체했고, OCR·탐지·사진 근거 판정은 실제 코드를 실행했다. 새 계정을 만들거나 로그인 설정을 바꾸지 않았다.

위치 라벨은 합성한 테스트 코드다. 테스트 결과의 `TEST_RACK_LABEL_MATCH`는 위치 라벨과 적재물 근거가 일치했다는 뜻이며, 실제 상품 SKU나 수량을 검증했다는 뜻이 아니다. 모의 재고의 수량 1은 포장 묶음 1건을 나타낸다.

새 사진은 이전 개선에 쓰인 촬영 묶음과 같은 묶음에서 골랐으므로 독립적인 현장 평가 세트로 해석하지 않는다. 잘린 적재물과 작은 포장도 일부 포함하며, 확인되지 않은 위치는 계속 보류한다. 이번 작업에서는 모델을 재학습하거나 판정 기준을 낮추지 않았다.
