# 얕은 선반 탐지 개선 — 2026-11-19.37

기존 팔레트 탐지기에 보조 선반 모델을 추가했다. 두 방식으로 재판독한 상품 코드가 있는 미확인 영역에서만 보조 모델을 실행한다. 원본 사진으로 환산한 실제 탐지 경계와 신뢰도를 보존하며, 서로 다른 입력에서 반복 확인된 후보를 사용한다. 상품과 위치의 최종 대조는 기존 F04가 수행한다.

## 동일 사진의 개선 전후

고정된 모의 라벨 사진 3장에 대해 업로드, JPEG 정규화, OCR, 적재물 탐지, 전산 대조를 처음부터 다시 실행했다. 탐지 누락과 확인 보류도 분모에 포함했다.

| 지표 | 2026-11-17.35 | 2026-11-19.37 |
|---|---:|---:|
| 정확한 자동 상품·위치 판정 | 8/11 (72.7%) | 9/11 (81.8%) |
| 정상 적재의 정확한 판정 | 6/7 | 7/7 |
| 오적재의 정확한 판정 | 2/4 | 2/4 |
| 확인 보류 | 3 | 2 |
| 잘못된 자동 판정 | 0 | 0 |
| 빈 칸의 잘못된 적재물 판정 | 0/1 | 0/1 |

추가로 확인된 위치는 모의 사진의 `HLA01-3F-03`이다. 상품 코드 `HPX-502`와 실제 파란 상자 묶음의 경계가 연결됐다. 사람이 표시한 경계와 IoU 0.50 이상도 충족했다. 나머지 미탐지 2건은 보류한다.

이 사진들은 여러 차례 개선에 사용한 **개발 회귀 검증 자료**다. 81.8%를 새로운 실제 창고의 정확도로 해석할 수 없다. 현장 검증에는 다른 랙 사진과 촬영 시점의 실제 전산 기록이 필요하다. 수량은 이 모델의 검증 범위에 포함하지 않는다.

## 학습 자료와 재현

- 추가 학습 세트: 학습 영역 30개, 검증 영역 4개(적재물 정답 14개). 동일 촬영 원본의 잘라낸 영역과 재촬영은 같은 그룹에 둔다.
- 학습에는 비닐 포장 팔레트 외에 진열용 상품 묶음과 빈 선반을 추가했다. `annotations.json`의 경계는 EXIF 방향을 적용한 원본 좌표다.
- 검증 그룹은 장난감 구역이며, 해당 그룹은 추가 학습에 사용하지 않았다. 회귀 사진의 촬영 묶음 `153240227`, `153410664`도 추가 학습에서 제외했다. 이 조건은 과거 기본 모델의 모든 사전 학습 자료까지 독립임을 주장하지 않는다.
- 촬영 그룹 및 분할 간 파일 중복 검사 통과. 재생성한 이미지·라벨 68개가 실제 학습 입력과 바이트 단위로 일치했다.
- 체크포인트는 분리된 검증 세트로 선택했다. 마지막 학습은 최적 20 epoch, 조기 종료 36 epoch다. 세부 지표와 체크포인트 계보는 `report.json`에 기록했다.

백엔드 폴더에서 실행한다. `INDEPENDENT_BASE_DATASET`은 앞선 단계에서 촬영 묶음을 제외한 데이터 폴더이고, `INITIAL_CHECKPOINT`는 이어서 학습할 가중치다. 준비 도구는 기존 출력 폴더를 덮어쓰지 않는다.

```powershell
.\.venv\Scripts\python.exe -B training/shelf_v37/prepare_dataset.py --base INDEPENDENT_BASE_DATASET --photos ORIGINAL_PHOTO_DIRECTORY --output NEW_DATASET_DIRECTORY
.\.venv\Scripts\python.exe -B training/shelf_v37/train.py --dataset NEW_DATASET_DIRECTORY --weights INITIAL_CHECKPOINT --output NEW_TRAINING_DIRECTORY
```

## 적용 및 검사

기본 가중치는 `runs/detect/shelf_v37/weights/best.pt`다. 별도 경로를 쓰려면 서버 시작 전에 `IVENAI_SHELF_MODEL_PATH`를 지정한다. 보조 가중치가 없는 환경은 기존 탐지기로 동작한다.

모델을 교체하면 서버를 재시작한다. `/health`의 `pipeline_version`이 `2026-11-19.37`, `shelf_detector_available`이 `true`인지 확인한다. 저장 결과에는 주 모델과 보조 모델의 SHA-256이 함께 포함되므로, 가중치가 바뀐 경우 이전 분석 캐시를 재사용하지 않는다.

기존 API·OCR·전산 대조와 새 경계 복구 검사를 포함해 백엔드 테스트 109개가 통과했다. 새 검사에는 상품 코드 충돌, 복수 경계 후보, 단일 입력의 중복 탐지, 이웃 칸 연결, 기존 판정 보호, 가중치 변경 시 캐시 무효화가 포함된다.
